# МетроОсмотр — серверная часть

FastAPI + SQLAlchemy. По умолчанию SQLite (файл `data/metro.db`), фото — в `data/storage/photos`.
API реализует `openapi.yaml` из проектирования (`/api/v1`, порт 8080 — как в блоке `servers`).

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --port 8080 --reload
```

При первом запуске БД создаётся и заполняется тестовыми данными (4 участка, 40 неисправностей, 4 пользователя).
Swagger UI: http://localhost:8080/docs. Пересоздать данные: `python -m app.seed --reset`.
Тесты: `python -m pytest -q` (34 теста, каждый прогон на чистой временной БД).

Настройки — переменные окружения или файл `.env` (см. `.env.example`). Для реального использования обязательно задайте `JWT_SECRET`.

## Авторизация

- `POST /auth/login` → access JWT (HS256, 15 мин) + refresh (UUID, 30 дней).
- Refresh одноразовый, с ротацией: после `/auth/refresh` старый токен перестаёт работать. В БД хранится только SHA-256 от refresh-токена.
- Роль и активность пользователя читаются **из БД на каждом запросе**, а не из токена: смена роли/блокировка действуют сразу.
- Пароли — scrypt с солью; на логин действует лимит 5 неудачных попыток за 60 с (429 + `Retry-After`).
- 401: `TOKEN_EXPIRED` (клиент один раз обновляет токен) / `INVALID_TOKEN` (выход на экран входа).

## Правила доступа на уровне строк (RLS)

Все условия видимости собраны в одном файле — `app/policies.py`; роутеры своих условий не содержат.

| Роль | Какие неисправности видит (SELECT) |
|---|---|
| DISPATCHER | все |
| WORKER, FOREMAN | свои записи **или** записи своих смен (бригадир/член бригады) **или** непроверенные (не `VERIFIED`) записи на участках своих смен |

| Действие | Кто может |
|---|---|
| Создать неисправность | WORKER, FOREMAN (смена должна быть своей и на том же участке) |
| PATCH полей | автор, бригадир смены записи, диспетчер |
| Сменить статус | любой, кто видит запись; `VERIFIED` — только FOREMAN/DISPATCHER |
| Загрузить фото | WORKER, FOREMAN, видящие запись |
| Создать смену | FOREMAN |
| Смена и её сводка | бригадир, члены бригады, диспетчер |

Чужая (невидимая) строка отвечает **404**, а не 403 — факт существования записи не раскрывается. 403 возвращается, когда строка видна, но действие запрещено. Условия применяются и к списку (фильтр по чужому участку вернёт пустой список), и к фото, и к сводке смены.

Важно: это RLS **на уровне приложения**. Это не `CREATE POLICY` в PostgreSQL — SQLite такого не умеет.

## Что добавлено сверх документа

- `GET /defects/{id}/photo` — скачивание фото. `photoUrl` указывает на этот эндпоинт (нужен заголовок `Authorization`; в Coil — через OkHttp-интерцептор с токеном). Публичной раздачи файлов нет, иначе обходился бы RLS. `?v=` в ссылке меняется при замене фото.
- Код `SHIFT_ID_CONFLICT` (409) — код смены занят другим бригадиром.
- Поле `categoryId` в `GET /defect-types` — тип зависит от категории; сервер проверяет соответствие при создании и правке.
- `GET /health` без авторизации.
- Заголовок `X-App-Version` ниже `MIN_APP_VERSION` → 426 `CLIENT_OUTDATED`.

## Особенности реализации

- Идемпотентность: повторный `POST /defects`, `POST /shifts` и `POST /defects/{id}/status` с тем же `id` не создаёт дубликат (200 вместо 201).
- Пагинация курсорная (keyset по `(detectedAt|picket, id)`), без пропусков и дублей; курсор от другой сортировки отклоняется (400).
- Фото: тип определяется по содержимому (JPEG/PNG), не по заголовку; лимит 5 МБ; запись атомарная (`os.replace`).
- Поиск `q` нечувствителен к регистру в кириллице (встроенный `lower()` SQLite этого не умеет — в `db.py` подменён Python-версией).
- Единый формат ошибок `{"error": {code, message, requestId, details}}` и `X-Request-Id` в каждом ответе, включая 500.

## Известные ограничения

- Лимит попыток входа хранится в памяти процесса (при нескольких воркерах он не общий).
- Повторное использование уже погашенного refresh-токена просто отклоняется; цепочка сессий при этом не отзывается.
- Тело загружаемого файла Starlette сначала принимает целиком, и только потом проверяется лимит 5 МБ; для продуктива лимит нужно дублировать на reverse proxy.
- PostgreSQL: достаточно задать `DATABASE_URL=postgresql+psycopg://...` и поставить `psycopg`, но в этой сборке проверялся только SQLite.
- HTTPS сервер сам не терминирует — ставьте за nginx/Caddy.

## Подключение с Android

Эмулятор обращается к хосту по `http://10.0.2.2:8080/`. Для отладочной сборки с обычным HTTP нужен `network_security_config` (cleartext только для `10.0.2.2`); адрес и версию API держите в `BuildConfig`.
